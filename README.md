# AetherLink 以太链接

[![ci](https://github.com/Hyaeve/aetherlink/actions/workflows/ci.yml/badge.svg)](https://github.com/Hyaeve/aetherlink/actions/workflows/ci.yml) [![docker](https://github.com/Hyaeve/aetherlink/actions/workflows/docker.yml/badge.svg)](https://github.com/Hyaeve/aetherlink/actions/workflows/docker.yml)

反代 Audiobookshelf / Emby / 飞牛影视的 x86 Docker 服务：拦截播放请求，读取库里的 `.strm` 指针，把播放器直接 **302** 到真实媒体地址，音频与视频字节不再经过媒体服务器。

前端 Vue 3 + Vite，后端 Go，最终产物是单个静态二进制（前端资源用 `go:embed` 打进二进制）。

**所有配置都在网页上完成。** compose 只需要一个 `./config` 卷：管理账号、上游地址与 API 密钥、反代端口、302 策略、路径映射全部在管理界面填写，保存即生效、无需重启容器。唯一需要动 compose 的地方是把上游的反代端口映射出去。

## 工作原理

```
播放器 ──▶ AetherLink:5152 ──▶ (非媒体请求) ──▶ Audiobookshelf:13378
                    │
                    ├─ 命中媒体接口 ──▶ 用 API 密钥问上游「这个媒体是什么」
                    │                  ↓
                    │        ┌─ 上游直接给出直链（Emby / 飞牛影视）──┐
                    │        ├─ 上游只给指针路径（ABS）→ 定位并读取 .strm ─┤
                    │        └─ 普通文件 ──▶ 原样透传给上游       │
                    │                                    ↓ 归一化 URL
                    └──────────────────── 302 Location: http://10.0.0.31:19527/d/xxx.m4a
```

**一个上游一个端口。** 每个上游在 AetherLink 上独占一个反代端口，路径与上游完全一致——
播放端只需要把地址里的端口从媒体服务器端口换成 AetherLink 的反代端口，别的什么都不用改。
管理界面自己占容器内的 5151（`AETHERLINK_PORT=8080` 可改），且只服务管理页与管理 API，不做反代。

- **拿到账号**：Audiobookshelf 与 Emby 用的是它们自带的静态 API 密钥（Audiobookshelf 的 Key 就是一枚 JWT，可作 Bearer 使用；Emby 用 `X-Emby-Token`/`api_key`），因此 AetherLink 能以该账号权限查询书库、条目和文件真实路径。飞牛影视没有这种静态密钥——它只认客户端账号密码换来的令牌，而这条令牌由播放器自己登录取得并随请求转发，所以**什么都不填也能完成 302**；只有想让 AetherLink 自己读媒体库时才需要填上账号密码，它会走同一条登录接口换令牌。
- **只拦截字节投递接口**，并在 Emby 系的 `PlaybackInfo` 中把客户端本来就能直放的 STRM 接到 AetherLink；其余请求（Web UI、封面、元数据、进度同步、客户端不兼容时的 HLS 转码）原样反代。
  - Audiobookshelf：`/api/items/:id/file/:ino`、`/api/items/:id/file/:ino/download`、`/public/session/:id/track/:index`
  - Emby / 飞牛影视：`/Videos|Audio/:id/stream(.ext)`、`/Items/:id/Download`
- **两种 strm 形态都认**：Emby 与飞牛影视在扫库时就把指针读成了 `MediaSources[].Path` + `Protocol: Http`，AetherLink 重写 `DirectStreamUrl`，下一跳即可 302 或中继。四种跳转模式一律把 STRM 媒体源压成 DirectStream 引回 AetherLink：上游判可直放时也要压，否则客户端会直连 `MediaSources[].Path` 里的网盘或 OpenList 直链，绕开 AetherLink，既不留 302 记录也不受内网直链安全网保护；上游判「当前客户端不能直接播放原始文件」时同样压，否则卡片上写的档位落不到这台客户端身上（飞牛对外网客户端常以码率限制为由拒绝直放，客户端于是转投上游转码 HLS）。压的时候会把「为什么不能直放」的理由字段一并清空，免得 PlaybackInfo 自相矛盾；`TranscodingUrl` 与 `TranscodingContainer` 一律保留，客户端真要回退时还能自己走。Audiobookshelf 只报告指针文件路径，AetherLink 自己定位并读取那个 `.strm`。
- **非 `.strm` 文件自动透传**给上游，不影响普通有声书和普通影片。读不到指针时同样退回透传，播放不会因为少挂一个目录而失败。
- **URL 归一化**是关键：STRM 生成器写进去的往往不是合法 URL。AetherLink 会补齐百分号编码，同时保留已编码序列，因此下面三种主流形态都能直接 302：
  - 115 pick code：`http://10.0.0.31:19527/d/bi6jeznun2rvu88v6.m4a?/001.总序.m4a`（查询串里的显示文件名会被识别为 `filename`）
  - openlist 中文路径带空格：`http://10.0.0.31:25244/d/移动云盘/.../白色巨塔 (2003) S01E01.再读.mkv`
  - openlist 已编码路径含 `%26`、`%20`：保持原样不二次编码

## 快速开始

```bash
mkdir -p config
docker compose up -d
```

浏览器打开 `http://宿主机:15151`（会自动跳到 `/aetherlink/upstreams`）：

管理页面使用独立后缀，刷新后会保留当前页面：`/aetherlink/upstreams`、`/aetherlink/logs`、`/aetherlink/settings`。

1. 用默认账号 **admin / password** 登录。
2. 进入「以太链接」，点虚线的「添加上游」卡片：选媒体类型（Audiobookshelf、Emby 或飞牛影视），填上游地址与反代端口——Audiobookshelf 填「设置 → 用户 → 该用户的 API Token」，Emby 填「控制台 → 高级 → API 密钥」，飞牛影视则**不需要任何密钥**（它没有静态密钥这东西，选中该类型后表单里给的是可留空的「登录账号 / 登录密码」，用于 AetherLink 自己去读媒体库）。保存前可以点「试连」当场确认地址是否可达。
3. 到「系统设置 → 管理账号」改掉默认账号密码。密码只以 PBKDF2-SHA256 的派生值存进 `config/config.yaml`，明文不落盘。
4. 「反代端口」表单里已预填一个空闲端口（默认 5152），把它加到 compose 的 `ports` 里再 `docker compose up -d`。
5. 播放端只改端口：`http://宿主机:13378` → `http://宿主机:5152`，路径不用动。

> 端口暴露在局域网时请务必先改掉默认账号：任何能访问这个端口的人都能用 admin / password 登录并读到上游 API 密钥。登录后界面顶部与设置页会一直提示，直到你改掉为止。

配置文件不存在时容器会自动创建，不需要事先准备任何文件（入口脚本以 root 启动，会先把 `/config` 的属主改成服务用户 10001，再降权运行主进程）。`deploy/config.example.yaml` 只是字段说明。

### 挂载说明

```yaml
volumes:
  - ./config:/config
  - ./cache:/cache
```

要不要额外挂媒体目录，**取决于上游是哪一种**。两种媒体服务器处理 `.strm` 的方式根本不同：

| 上游 | 谁读 `.strm` | AetherLink 需要挂媒体目录吗 |
| --- | --- | --- |
| **Emby / 飞牛影视** | 上游自己，在扫库阶段就读掉了。库里项目仍是 `.strm` 路径，但它的 `MediaSources[].Path` 直接是指针里的那条直链（`Protocol: Http`）。 | **不需要**。直链由上游的 API 给出，AetherLink 一个文件都不用看就能 302。 |
| **Audiobookshelf** | Audiobookshelf 保留指针原样，播放时自己去读、自己代理。它的 API 只报告指针文件的路径。 | **需要**。AetherLink 得亲自读到那个 `.strm` 才知道要跳到哪里。 |

所以只反代 Emby 或飞牛影视时，`./config:/config` 一个卷就够了。要给 Audiobookshelf 做 302，就得把它的媒体目录也挂进 AetherLink：

```yaml
  - /vol1/1000/NetDisk/115-Strm/Set/Read:/audiobooks:ro
  - /vol1/1000/NetDisk:/NetDisk:ro
```

**挂载点不必和上游同名。** AetherLink 会自己定位指针：先按路径映射翻译，找不到就把上游路径逐段剥掉前缀，在你配的根目录、映射目标以及 `/NetDisk`、`/audiobooks`、`/media`、`/strm`、`/data` 这些常见挂载点下逐个查。上游报的是 `/audiobooks/Set/Read/Book/001.strm`、你只挂了 `/NetDisk/...`，一样能找到。定位始终受「STRM 允许根目录」白名单约束，白名单外的路径连 stat 都不做。真正需要手写路径映射的只剩那些完全对不上的目录结构。

**读不到指针不会让播放失败。** AetherLink 会退回纯透传，让 Audiobookshelf 自己代理这一轨——播放照常，只是没有 302。日志里会写明原因（「读不到 strm 指针，本次退回透传」），把媒体目录挂进来即可恢复 302。

容器以非 root 用户（uid 10001）运行，被挂载的目录需对该用户可读。

`./cache:/cache` 用于持久化 iOS 音频适配缓存。AAC 重新封装或 WMA 转码后的文件会按书名放在 `/cache/<书名>/` 下，并保留原音频文件名（输出扩展名统一为 `.m4a`）；不同 UA 的缓存变体放在内部键目录中，避免互相覆盖。连续 2 小时没有再次获取请求后，AetherLink 会自动删除；一本书的转码文件全部删掉之后，剩下的空书名目录（连同它下面的键目录）也一并删掉。此外，每次容器启动时、以及容器每运行满 24 小时（24h、48h、72h…）时，还会把 `/cache` 整扫一遍，把上一次没来得及收尾、或手动删掉缓存文件后残留的空目录一起收掉；这些都只删空目录，缓存根目录本身始终留着。关于 Audiobookshelf 那份 compose 里的 `./podcasts:/podcasts`：那是 Audiobookshelf 的播客库目录，用来存它自己下载的播客音频。AetherLink 不需要它——播客是真实文件，走透传交给上游处理。

播放流水统计会持久化在 `/config/playback-stats.json`，重启后恢复最近保留的播放事件与统计数据。会话令牌**不落盘**：勾了「保持登录」的会话固定 7 天、不随使用顺延，但只对这个浏览器有效，容器一重启同样要重新登录；不勾的普通会话 12 小时、随用顺延，也只在内存里。

本地开发：

```bash
cd web && npm install && npm run build   # 产物写入 internal/web/dist
cd .. && go run ./cmd/aetherlink -config ./config.yaml
```

前端热更新：`cd web && npm run dev`（Vite 会把 `/aetherlink/api` 代理到 `127.0.0.1:5151`）。

## 容器起不来怎么排查

先看日志，`restart: always` 会把启动失败伪装成「一直重启」：

```bash
docker logs AetherLink
docker inspect -f "{{.State.ExitCode}} {{.State.Error}}" AetherLink
```

| 日志里的现象 | 原因与处置 |
| --- | --- |
| `加载配置失败: ... permission denied` | 入口脚本会自动把 `/config` 的属主改好，用当前镜像不该再出现。仍出现说明你在 compose 里加了 `user:`（脚本没有改属主的权限），在宿主执行 `chown -R <那个uid>:<那个gid> ./config` 即可。 |
| `[entrypoint] 错误：/config 必须可写` | 卷被挂成了只读。检查 compose 的 `volumes` 有没有多写结尾的 `:ro`。 |
| `解析 /config/config.yaml 失败` | 手改过配置文件且 YAML 写坏了，或写了程序不认识的字段（配置是严格解析的）。改回去，或直接删掉该文件让程序重建。旧版的 `prefix` 字段会被自动升级成 `listen_port`，不会再报这个错。 |
| `redirect.mode "xxx" 必须是 always、public、private 或 never` | 手改配置或环境变量 `AETHERLINK_REDIRECT_MODE` 填了非法值。 |
| `listen tcp :5151: bind: address already in use` | 管理端口被占，通常是某个上游的反代端口和它撞了。管理端口固定 5151，把上游端口改成别的。 |
| `端口 xxxx 无法监听（可能已被其他程序占用）` | 该反代端口在容器内已被占用（多半是两个上游撞了端口，或与管理端口 5151 冲突）。在界面上改成别的端口保存即可，原有上游不受影响。 |
| 播放端连不上反代端口 | 端口没在 compose 的 `ports` 里映射出去。加一条 `- 5152:5152` 再 `docker compose up -d`。 |
| `读不到 strm 指针，本次退回透传` | Audiobookshelf 的媒体目录没挂进 AetherLink，只能透传（能播但没有 302）。按「挂载说明」把媒体目录挂进来即可。Emby 与飞牛影视不会出现这条。 |
| `检测到 Emby HLS 转码请求 ... hls1/main/*.ts` | HLS 分片本身不能 302。正常形态不该出现：PlaybackInfo 已经把 STRM 源引回 AetherLink，客户端若还来要转码分片，多半是它在用上一轮缓存的播放协商结果，停止并重新开始播放即可。飞牛影视的 HLS 请求也会打这条日志。 |
| `中继 ... 直链是内网地址而客户端在外网` | 该 strm 指到的地址本身就在局域网里（典型是 OpenList 开了「本地代理」，它要么原地出流，要么回一跳后落点仍是自己的内网地址），302 出去外网客户端也连不上，所以改由 AetherLink 中继。想拿到真正的 302，只能让该服务关掉本地代理输出真直链，或把它发布到公网。内网客户端播放不受影响，照常 302。 |
| 内网的客户端却拿到了 302（「公网跳转」下） | 客户端地址被算成了公网。最常见的原因：它走 IPv6，而家里设备拿到的正是运营商下发的全局地址（`240e::` 这类 GUA）——内置判断按地址类型分类，GUA 就是公网；IPv4 侧同理，局域网若不是 `10/8` / `172.16/12` / `192.168/16`（运营商 CGNAT 的 `100.64/10` 就属于这种），内置规则也不认。**先看系统设置「网络地址」卡片上那行「本机网段」**：与本机同网段的客户端本来就自动按内网处理（IPv4 与 IPv6 的直连网段都算），那一行只要不是空的就不会走到这里。它是空的说明容器看不到局域网网段（多半不是 host 网络），这时改用 host 网络，或手改配置文件把自家网段写进 `redirect.intranet_cidrs`（每行一个 CIDR，取日志里客户端地址的前 4 段加 `::/64`）。同一批客户端在「内网跳转」下则是被漏掉的那一半。一条 TCP 连接只有一个对端地址，从 IPv6 连接里问不出客户端的 IPv4，所以没有能自动推断的解（想彻底避开，也可以让内网域名不解析 AAAA、或让播放器只用 IPv4）。 |
| 日志写「客户端 IP 无法识别」 | 这次请求拿不到可用的来源地址：AetherLink 直接看到的 TCP 对端是空地址或组播地址，或者前面的反向代理既没覆盖 `X-Real-IP`、也没往 `X-Forwarded-For` 追加真实来源。条件跳转模式对它一律中继。前面确实有反代时，把**那个反代自己的地址**写进系统设置「网络地址」→「可信前置代理 IP/CIDR」（只写代理本身，不要写整个客户端网段），它转发来的头才会被采信。 |
| `中继上游断流` / `中继写回客户端结束` / `中继不完整` | 中继每一行明细都写明上游状态码、转发字节、客户端 `Range` 与**回给客户端的整幅响应头**（`Content-Type` / `Content-Length` / `Content-Range` / `Accept-Ranges`）——播放器只看得到这半边，出问题时它必须在日志里，否则只能猜。`中继上游断流` 是上游（含网盘驱动）提前断流而客户端还在等，播放必然卡住——问题在源，不在 AetherLink；`中继写回客户端结束` 是客户端先走了（播放器断开、网络中断），日志写明已转发的字节数；`中继不完整` 是转发量低于上游声明的长度。`中继被客户端中断` 也记一行并写明已转发字节：拖动进度条、切集的正常形态与「播放器不认我们回的响应」共用这个出口，靠字节数区分。客户端断开会让上游请求一起被取消、读端因此也报错，所以那一支把读到的错误附在末尾并注明「多为连带现象」；**只有客户端还在等时读到错误，才会报成 `中继上游断流`**。转发量低于 64KiB 时那一行会从 `info` 升级成 `warn`，并把**客户端请求头与回给客户端的完整头**一并列出来（凭据已打码）：那种「读了一点就走」的形态，双方的头是唯一能定论的东西，不该让人先跑去改日志级别。 |
| `中继 ...（状态 206，几百 ms）` 之后播放器立刻报错，且日志里没有别的明细 | 字节已经从中继取回来了，是播放器读完响应头就断开——`中继被客户端中断` 那一行会写明它到底吃了多少：只有几十 KB、远小于 `Range` 要的长度，就是播放器主动离开；已接近 `Range` 长度则只是拖了进度条。转发量低于 64KiB 时该行升级成 `warn`，并把**客户端请求头与回给客户端的完整头**一起列出，不必先改日志级别。中继**原样转发上游的 `Content-Type`**（见「已知取值边界」），它与直连时播放器拿到的是同一个值，不会是差异来源。剩下两个成因分属两边：库里的 STRM 名（来自上游的 `Container`）与真实文件不符——同行的 `播放器可能据此选错解复用器` 会直接指出来（上游回中性类型 `application/octet-stream` 时，中继会读一眼响应体开头的那 16~128 字节来对账，所以网盘 CDN 上照样会有这条），根治要改 STRM 名或上游的 `Container`，拿 302 也一样踩；以及**播放器自己判定这个文件放不了**（编码、位深、多字幕轨都可能）。想分清这两者只需一个动作：**同一片切「始终跳转」再播一次**——能播就说明是这个播放器不认某种投递方式（与中继无关），此时只剩「把这张卡片整体切成 302 档位」这一条路——中继与 302 只能整卡二选一（卡片上那格「不中继的客户端」名单已经删掉）；AetherLink 这一侧也没有「把这类客户端交回上游转码」的开关。同样不能播则问题在文件名与真实容器不符，或文件本身解不了。 |
| `中继交换明细`（只在日志级别 = `debug` 时出现） | 排障用的完整 HTTP 交换：客户端请求头、AetherLink 发给上游的请求头、上游的状态码与**全部**响应头、以及回给客户端的头（凭据类字段已打码）。后面还会跟一行 `中继判容器读了 N 字节`，把用于判断容器的**原始字节**以十六进制列出来。绝大多数「同一片 302 能播、走中继播不了」的差异都藏在某个头里，info 级别只摘四个字段不够定论——要对比时在设置页把「日志级别」改成 `debug`（或给容器加 `AETHERLINK_LOG_LEVEL=debug`）重播一次即可，看完记得改回来。「客户端读了一点就走」那一支是唯一的例外：它本身就在 info 级别把双方的头写全了，不必开 debug。 |
| 能播但日志里全是 `passthrough`，没有 302 | 上游把这一轨报告成了普通文件。Emby / 飞牛影视侧检查项目是不是真的 `.strm` 库（AetherLink 认 `Protocol: Http` 或 `Container: strm`）；Audiobookshelf 侧确认媒体目录已挂载。飞牛影视的接口都挂在 `/emby` 前缀下，AetherLink 对自己发出的 API 调用和转发的播放协商请求都会自动补上这个前缀，不必改播放器配置。界面「运行日志」页的播放流水里，这一行的「目标」列会写明具体原因。 |
| `PlaybackInfo 改写缓存未命中（…，播放器请求带来的令牌：有/无）` | 这条 `/stream` 没能用上改写 PlaybackInfo 时缓存下来的媒体源，AetherLink 只能回头问一次上游。**这就是「同一片、什么都没改、时好时坏」的入口**——缓存命中时解析根本不问上游（也正是「点开就能播」的常态），没命中时才全看这次查询。缓存只活 10 分钟，而且按「条目 + 上游给的媒体源 Id」存；播放器沿用上一次协商结果、或自己拼的 `/stream` 不带 `MediaSourceId` 时都会落进这里（请求没带 Id 而该条目下只有一条缓存时，现在会直接用它，不必回头查）。后半句写明这次有没有可借用的播放器令牌：飞牛卡片没填账号密码时，令牌是**唯一**的鉴权来源。 |
| 飞牛影视偶尔只有一两条播放不跳转 | 见上一条：PlaybackInfo 改写后的媒体源只缓存 10 分钟，过期后要么由客户端重新协商、要么由 AetherLink 自己回头查一次上游（走飞牛的播放协商路由，不是条目路由）。这次回头查在飞牛上要凭据：卡片填了账号密码就用管理员身份，没填就只能借用播放器自己带在请求上的令牌——而我们生成的 `DirectStreamUrl` 里本来就不含令牌，带不带全看播放器。写「令牌：无」的那次查询必然失败（飞牛会拒，或者回一整页单页应用 HTML），于是退化成透传；透传出去的请求同样没鉴权，上游也放不了，表现就是「播放不了」。**再试几次又好了**，是因为客户端重新做了一遍播放协商、缓存又被写热。要根治，给卡片填上账号密码。 |
| 能进库、能浏览，一播放就失败：`解析 strm 目标失败 ... invalid character '<' looking for beginning of value` | 上游把 AetherLink「取条目」的请求当成了不认识的路径，回了一整页网页（还带着 HTTP 200）而不是 JSON，解码在第一个 `<` 上就断了。根因是飞牛影视的 Emby 兼容层只实现了客户端真正会调的那几条路由：`/Items` 与 `/Items/{id}` 都落回单页应用，只有播放协商 `/Items/{id}/PlaybackInfo` 是真的。现在飞牛改为优先走 PlaybackInfo、把它的媒体源直接当条目用，条目路由退居兜底（Emby 仍集合路由优先）；失败时错误信息里会写**实际请求地址**、`Content-Type`、是否携带令牌与响应开头，可以直接照着核对。升级到修复版本后重启容器即可。 |
| 日志里一条播放记录都没有 | 播放请求没被识别成媒体请求。看日志里有没有 `未识别的疑似播放请求`：有就把那条路径贴出来（说明拦截规则漏了它）；完全没有，说明播放器根本没走 AetherLink 的反代端口，检查播放端地址里的端口有没有换过来。 |
| 没有任何日志、`ExitCode` 是 127 或 `exec format error` | 镜像架构不对。本项目只发 `linux/amd64`，ARM 设备（树莓派、某些 NAS）跑不了。 |

### 配置目录的属主

默认不需要管：容器以 root 进入入口脚本，脚本把 `/config` 的属主改成服务用户（uid 10001）后降权运行主进程。属主实在改不动时（部分 NAS 的 SMB/NFS 挂载、带强制 ACL 的存储池）脚本会退回以 root 运行，宁可让你进得去界面，也不陷入重启循环。

想让配置文件归某个特定用户，加两个环境变量即可，仍由脚本自动完成：

```yaml
    environment:
      - PUID=1000
      - PGID=1000
```

只有当你坚持用 compose 的 `user:` 时，脚本才没有改属主的权限，需要自己在宿主准备好目录：

```bash
mkdir -p config && sudo chown -R 1000:1000 config
```

## 管理界面

| 页面 | 作用 |
| --- | --- |
| 以太链接 | 每个上游一张卡片，卡片直接显示名称、媒体类型、`地址:端口`、`原端口 → 反代端口`、跳转模式与状态。左键卡片打开详细编辑窗口，点击反代端口可打开对应入口，右键弹出菜单（测试连接 / 停用启用 / 删除）。保存立即生效。 |
| 运行日志 | 上半是**播放流水**：每条播放请求最终是 302、透传、中继还是失败，逐条列出请求路径、跳转目标、缓存有效期与耗时，可按结果过滤、滚动浏览（虚拟列表，一次只渲染视口附近的行，不分页）；一次都没 302 时页面会直接给出最可能的原因。「目标」与「UA」两栏可直接点击复制；UA 栏复制的是箭头**左边**那个客户端原始 UA（右边是按配置改写后发给上游的 UA），因为它是唯一能直接粘进「屏蔽 UA」名单或上游 UA 匹配里的值。下半是内存环形缓冲的运行日志，按级别过滤、滚动浏览（同样不再分页；日志正文按原文折行显示，长行不会被截成一行）。默认保存 5000 条。 |
| 系统设置 | 缓存、日志级别、修改管理账号。每个上游的跳转模式在对应卡片的编辑窗口中单独设置。 |

界面是莫奈低饱和浅色主题：取色自睡莲与干草堆的晨蓝、水草绿、藕紫与淡金，页面底层有一层极缓慢漂移的水色光斑，卡片渐变也随之流动（周期几十秒，系统开启「减少动态效果」时自动静止）。左侧一列图标做页面切换，侧栏右边缘那道竖线就是展开 / 收起按钮，展开后图标旁会显示文字（状态记在浏览器本地，刷新后保持）。

反馈分两种：会改变页面状态的用页面顶部横栏（例如加载失败、需要处理的问题），看一次就够的用**页面底部中央的悬浮提示**——毛玻璃圆角框，亮几秒自己淡出。右键菜单里的「测试」走后者：不占布局、不会把下面的卡片顶下去，测试中显示转圈、成功显示对勾、失败显示叉，失败信息停留得久一些（6 秒，成功 4 秒），连续点多次只会保留最新一条。

登录页的账号要自己输，不预填任何名字（后端自举只回报版本号与密码长度下限）。密码框统一是**默认一串圆点**——登录页、设置页「登录账号」卡片、上游编辑窗口的密钥 / 密码都一样，点输入框右侧的小眼睛看明文（图标变成斜线眼睛），再点一下回到圆点。设置页「登录账号」卡片的账号框则常驻显示当前账号，改过名也能对上。

### 配置项说明

| 项 | 说明 |
| --- | --- |
| 跳转模式 | 在上游卡片中设置字节去向：`always` 始终跳转；`public` 公网客户端 302、内网客户端中继；`private` 内网客户端 302、公网客户端中继；`never` 始终中继。按客户端真实 IP 分流，不按域名判定；内网包含私有、回环、链路本地地址与本机直连网段，检测结果显示在「网络地址」。容器无法看到实际局域网网段时可配置 `redirect.intranet_cidrs`；无法识别客户端 IP 时条件模式回退中继。四档共用 STRM 解析，均将媒体源引回 AetherLink 的 DirectStream，不额外验证播放权限。开启跟随 302 后，公网客户端遇到内网直链会中继兜底。飞牛非始终跳转档位的黄色标记提示部分播放器存在中继兼容性风险，不代表只有这三档会发生缓存过期或令牌失效。四档图标分别为跳出方框、地球、房子与折返箭头。 |
| 可信前置代理 IP/CIDR | 在系统设置的「网络地址」中填写，每行一个，例如 `192.168.1.10/32` 或 `fd00::10/128`。只填写实际前置代理，默认不信任任何转发头。可信代理须正确覆盖 `X-Real-IP` 或追加真实来源到 `X-Forwarded-For`；多层代理从右向左检查，取首个不可信节点作为客户端。不要填写整个客户端网段。 |
| 内网网段（`intranet_cidrs`） | **界面上没有入口，只能手改配置文件**（`redirect.intranet_cidrs`），每行一个网段，例如 `240e:390:1a2b:3c4d::/64` 或 `192.168.0.0/16`。命中即按内网处理，用来补齐内置判断：内置只认 RFC1918 / 回环 / 链路本地 / IPv6 ULA(`fc00::/7`)，而运营商下发给家里设备的 IPv6 全局地址按地址类型算公网——「公网跳转」会错误地 302 给它、「内网跳转」又会漏掉它。一条 TCP 连接只有一个对端地址，从 IPv6 连接里问不出客户端的 IPv4，所以只能把自家网段写在这里。填 `0.0.0.0/0` 或 `::/0` 会被拒绝：那等于让内外网判断失效，该用跳转模式表达。**多半不必填**：与 AetherLink 本机同网段的客户端已经自动按内网处理（IPv4 与 IPv6 的直连网段都算，见「跳转模式」，系统设置「网络地址」卡片上那行就是检测结果），这一项只留给容器看不到局域网网段（bridge 网络）或要额外声明别的网段的场合。 |
| 先跟随上游 302 | 播放前把跳转链走完，把最终直链交给播放器。适合 115 这类二次跳转后端，代价是首次播放多一次预检。 |
| 转发播放器 User-Agent | 部分网盘直链与 UA 绑定时必须开启；客户端未带 UA 或只有空白时，服务端使用回落 UA，未配置则用 `AetherLink`。302 无法替播放器设置下一跳 UA，若客户端不发送或自行改变 UA，建议改用中继；两层缓存均隔离 UA，唯一例外是直链缓存里的移动云盘（`cmecloud.cn`）那一档 —— 它跨 UA 共用同一条直链，见「直链缓存策略」。 |
| 屏蔽客户端 UA | 在系统设置的「安全与代理」中开启后，可按行填写 UA 关键词；命中后直接拒绝该客户端请求并返回 403。例如填写 `Filmly` 可拦截 `Filmly/99.0.0-217`。 |
| 直链缓存策略 | Emby 与飞牛影视保存已解析出的 STRM 直链，若直链带有数字 `t` 参数，则按 `t` 表示的实际到期时间动态缓存；未带有效 `t` 时固定保存 2 小时。Audiobookshelf 固定保存 15 分钟。**所有直链统一封顶 24 小时**：不管 `t` 报到多久、也不管配置里那一档回退值有多大，超过 24 小时一律按 24 小时缓存（不到 24 小时照原样保留，已过期的照旧不缓存）。**直链里含 `cmecloud.cn`（移动云盘）的固定缓存 15 分钟**，这一档不看直链自带的 `t` —— 更早、更晚、已过期、不是时间戳统统按 15 分钟（这条是内置规则，没有开关）。缓存落盘在 `/config/direct-links-cache.json`，重启后会恢复未过期的直链。日志会区分首次获取与命中缓存，并以 `min` 或 `h min` 显示剩余有效期。**移动云盘那一档不绑定 UA**：缓存期内同一个文件被别的播放器（UA 与令牌都不同）请求时，直接把已解析出的直链给它，不再回头问上游；其余直链仍按 UA 与播放器身份各自缓存。缓存**写在把直链交给客户端之后**：请求只改内存，由后台协程等你不再连着请求了才合并写一次盘，所以 302 的响应速度不受缓存影响。代价是进程被强行杀掉时可能丢掉最后一小段改动；正常停止服务与在设置页保存配置都会补写。 |
| 反代端口 | 该上游在 AetherLink 上独占的端口。播放端把地址里的上游端口换成它，路径保持原样。改动后要在 compose 的 `ports` 里同步映射。 |
| 媒体类型 | Audiobookshelf 填 API Token，Emby 填 API 密钥。飞牛影视账号密码可同时留空；试连可探测公共服务信息，填写凭据可查询媒体库并在缓存未命中时辅助解析。Emby/飞牛读取直链缓存前不额外验证播放权限，也不签发短期播放凭证。 |
| 查看已保存的密钥 / 密码 | 秘密平时以一串圆点显示，看明文点输入框右侧的小眼睛（图标变成带斜线的眼睛，再点一下又遮蔽回去）。列表接口只回报 `hasApiKey` / `hasPassword`，真正的值由编辑窗口在打开时单独取一次（`GET /upstreams/{name}/credentials`，需要登录，会在运行日志里留一行审计）。所以圆点一直是「有值」的状态，不存在「留空即保留原值」这种要记的规矩：框里是什么就存什么，清空才等于删除。若那次读取失败，窗口会提示，并且此时保存会保留原值、不会把密钥抹掉。新增上游没有旧值可取，两个框都是空的。 |
| 路径映射 | 上游看到的媒体路径 → AetherLink 容器内路径。两侧挂载一致时留空。 |
| STRM 允许根目录 | `.strm` 指向本地文件时允许读取的目录白名单，防止指针被用作任意文件读取入口。 |

正常使用不需要任何环境变量。仅保留几个容器级开关：

| 变量 | 用途 |
| --- | --- |
| `TZ` | 时区，影响日志时间戳。 |
| `AETHERLINK_CONFIG` | 配置文件路径，镜像内已设为 `/config/config.yaml`。 |
| `AETHERLINK_ADMIN_TOKEN` | **应急令牌**，可绕过账号登录。仅在忘记管理密码时临时加上，排障后请移除。它只在这台容器的这次启动里生效，不会被写回 `config.yaml`。 |
| `AETHERLINK_PORT` | **容器监听端口**，只写端口号（如 `8080`），不填即默认 `5151`。compose 里同一个变量既能改容器内监听、又能改端口映射：<br>`environment: [ AETHERLINK_PORT=8080 ]` + `ports: [ "15151:8080" ]`。改完记得重启容器。 |
| `AETHERLINK_LISTEN`、`AETHERLINK_LOG_LEVEL`、`AETHERLINK_REDIRECT_MODE`、`AETHERLINK_FOLLOW_REDIRECTS` | 启动期覆盖，用于排障。`AETHERLINK_LISTEN` 接受完整地址（`:8080`、`127.0.0.1:8080`），与 `AETHERLINK_PORT` 同时存在时以它为准。 |

忘记密码的另一种恢复方式：删掉 `config/config.yaml` 里的整个 `auth:` 段并重启容器，AetherLink 会重新写入内置的 admin / password，上游配置不受影响。

## 安全说明

- 管理界面有独立账号，与上游账号无关。首次启动写入内置的 admin / password，请尽快在设置页改掉。未登录访问管理 API 一律返回 401；只有 `/aetherlink/api/health` 与 `/aetherlink/api/bootstrap` 免鉴权，后者只回版本号与密码长度下限——不回显账号、凭据，也不透露是否仍在用默认账号，登录页因此不会给扫端口的人任何线索。当前账号名只在登录之后由 `/config` 提供（设置页「登录账号」卡片用它带出账号框）。
- 会话令牌分两类，但**两类都只在内存里**，容器重启后全部失效。不勾「保持登录」时是普通会话，12 小时有效、随用顺延；勾上「保持登录」则签发固定 7 天、不随使用顺延的会话，且只对这个浏览器有效——**容器不重启的前提下**，七天内不必再登录。内存里存的也只是令牌的 SHA-256，进程内存被 dump 也换不出可用令牌。修改账号或密码会立即注销所有会话。前端把「带着令牌还被回 401」统一当作会话失效（`api.js` 的 `request`）：清掉本地令牌、直接退回登录页，**不显示任何错误文案**——容器重启后刷新页面看到的就是干净的登录页，而不是一句「会话无效或已过期，请重新登录」。各页面的错误横栏都走 `visibleMessage()`，会话失效时它返回空串；登录口令错误的 401 不带令牌，不走这条路，仍然照常提示「账号或密码不正确」。
- 配置接口（`GET /upstreams`）只回报 `hasApiKey` / `hasPassword` 两个布尔，不随列表下发任何秘密；要看明文必须显式调 `GET /upstreams/{name}/credentials`，它走会话鉴权并在运行日志里留一行审计。飞牛的登录账号本来就不是秘密，列表与编辑窗口都直接回显。`config.yaml` 以 0600 权限原子写入。
- `.strm` 指向容器本地文件时，目标必须落在「STRM 允许根目录」内且必须是普通文件。
- Emby / 飞牛读取直链缓存前不额外验证播放权限，不签发短期播放凭证，也不新增权限检查 API 请求。命中缓存不代表播放端身份已获上游确认；缓存隔离不是访问控制。反代端口应由 NAS、防火墙或前置代理限制访问，不应仅依赖上游登录界面保护缓存中的媒体。
- 修改卡片服务器地址、媒体类型、凭据或路径规则后，旧直链不会被新配置命中；日志输出会隐藏访问令牌等凭据。旧格式直链缓存需重新获取一次。
- 302 的 Location 是可直接访问的媒体直链；不希望暴露媒体目标时，在对应上游卡片中把跳转模式设为 `never`。
- 运行日志播放流水中的「客户端 IP」与内外网判断使用同一来源。旧流水保留历史记录，不会重新推断 IP。若 NAT/隧道隐藏了真实客户端，且没有可信代理传递来源，日志只能显示直连节点地址；内网域名建议使用内网 DNS 解析到局域网入口。IPv6 按地址类型判断，全球可路由地址视为公网；但**与 AetherLink 本机同网段的客户端自动按内网处理**（IPv4 与 IPv6 的直连网段都算），所以运营商下发的全局地址（`240e::` 这类，家里设备拿到的常是它）不会被误判成公网——检测结果就显示在系统设置「网络地址」卡片上（容器不是 host 网络时看不到局域网网段，那行为空，这时只能手改配置文件的 `redirect.intranet_cidrs`）。代价说清楚：本机若挂在一个公网 IPv4 子网上（VPS 的 `/29` 那种，同段里坐的是别人），同段的地址也会被算成内网——多数云厂商给的是 `/32`，等于不受影响。
- 卡片配色由服务启动时间与名称共同生成，同次容器运行期间刷新浏览器保持一致；重启服务后重新分配低饱和莫奈渐变，动画持续流动。

## 已知取值边界

- Audiobookshelf 的 `/public/session/:id/track/:index` 走的是「打开会话」接口，只有会话属主或管理员可读。若配置的 API 密钥不属于管理员，该路径会退化为普通反代（普通播放走 `/api/items/:id/file/:ino`，不受影响）。
- Emby 的 HLS/转码分段路由不拦截：AetherLink 只管 STRM 那一跳（302 或中继），客户端若回退上游转码，HLS 分片照旧原样交给上游。飞牛影视的网页播放器还会被改写掉 `crossorigin="anonymous"`，否则浏览器会拒绝播放 302 出去的跨域直链。四档跳转模式都不会把 STRM 媒体源留给上游直连：一律压成 DirectStream 引回 AetherLink——上游判可直放时的 DirectPlay 会被关掉（否则客户端会直连 `Path` 绕过 AetherLink），引回之后按本档模式 302 或中继（条件跳转模式按客户端来源分派）。「上游说这个客户端不能直放」的那一半同样不再采纳（那个可以把它关掉的开关已经删掉）：客户端一律拿到原文件的直链。代价是「客户端真解不了原文件」的情况（网页端放 H.265 之类）也照原样送出去，没有退路了。
- 中继模式转发 `Range`、`If-Range`、`Content-Range`，seek 行为与直连一致。回给客户端的整幅响应头以上游为准（`Content-Length`、`Content-Range`、`Accept-Ranges`、`ETag`、`Last-Modified`、`Content-Disposition` 都原样带过去，保持定长响应、绝不退化成 chunked，否则播放器拿不到总长度、moov 在文件尾部的 MP4 无法 seek）。**`Content-Type` 同样原样转发——中继不改上游给的类型。** 网盘 CDN（115 等）与移动云 EOS 对视频一律回中性类型 `application/octet-stream`，播放器拿到它会自己按内容嗅探；替它改写成 `video/x-matroska`、`video/mp4` 这类具体类型，等于凭空造出一个 302 没有的差异。线上就有一例：同一片走 302（播放器拿到 CDN 的中性类型）能播，走中继（拿到被改写的 `video/x-matroska`）只读了 7.1KiB、把 MKV 的 `Tracks` 读完就断开——两边可观测的差异只剩 host 与这一个头。**中继与直连交给播放器的响应要逐项等价，包括类型**；`internal/proxy` 里有一条走真实 TCP 的测试把中继与直连的七个头逐项对比，钉住这件事。只有上游**压根没给** `Content-Type` 时（罕见）才由 AetherLink 补一个，顺序是**先字节、后扩展名**：先看**响应体开头的魔数**（`ftyp` 家族按品牌分视频与纯音频、EBML 的 Matroska 与 WebM、RIFF 的 AVI 与 WAV、`OggS`、`fLaC`、ASF；只对从文件开头开始的单段 `Range` 生效，判断用的字节原样写回客户端，不丢一字节），魔数认不出来才退回直链扩展名。连补类型时也不能让扩展名压过字节：网盘上「文件名写 `.mkv`、内容其实是 MP4」很常见，按扩展名回 `video/x-matroska` 就是让播放器拿 matroska 去解 MP4 字节。唯一例外是纯音频扩展名（`.m4a` / `.m4b` / `.m4p` / `.mp3` / `.flac` / `.opus` / `.ogg` / `.aac` / `.wav` / `.wma` / `.mka` / `.webma`）：MP4 家族里有声书与视频共用容器头，品牌字段常是 `isom` / `mp42`，字节根本分不出「这是音频」，扩展名才是唯一线索，所以这一类直接采信扩展名、不再看字节。另外，客户端按上游的 `Container` 请求 `/Videos/{id}/stream.mkv` 而实际类型与它不符时会打一行「`播放器可能据此选错解复用器`」——那是库里的名字与真实文件对不上，302 与中继都会踩，中继只是会把它写进日志。
- 飞牛影视的登录令牌由 AetherLink 自己换取并缓存 6 小时，全程只在内存里，不落盘。飞牛只认 `X-Emby-Authorization` 这个**完整**的客户端身份头，Emby 那种 `X-Emby-Token` 简写形式会被它直接 400 拒掉（报「X-Emby-Authorization is missing」），所以 AetherLink 两枚一起发。令牌被上游吊销（改密码、在别处登出、服务端重启）后的第一次调用会撞 401，AetherLink 会自动重登一次再重试，不会把一次令牌过期表现成「上游坏了」。
- 管理端口无法热改：在配置里改了 `server.listen` 之后界面会提示需要重启容器。上游的反代端口可以热改热增删，但新端口要在 compose 里映射出来才能从外部访问。

## 镜像构建

镜像由 GitHub Actions 构建，只出 **linux/amd64（x86_64）** 一个平台：

| 工作流 | 触发 | 产物 |
| --- | --- | --- |
| `.github/workflows/ci.yml` | push 到 main、PR、手动 | `gofmt` / `go vet` / `go test`，以及 `npm run build` |
| `.github/workflows/docker.yml` | push 到 main、打 `v*` 标签、手动 | 推送镜像到 `ghcr.io/hyaeve/aetherlink`，并起容器跑一次健康检查冒烟 |

标签规则：main 分支出 `latest` 与 `main`；打 `v1.2.3` 标签时额外出 `1.2.3`、`1.2`、`1`；每次构建都带一个 `sha-xxxxxxx`。二进制里的版本号来自 `VERSION` 构建参数（`-X main.version=`），容器内 `/aetherlink --version` 可查。

首次推送后需要在仓库 Settings → Actions → General 里确认 workflow 有 `packages: write` 权限（工作流已声明），GHCR 包默认为私有，公开使用请在包页面改成 public。

本地构建（需要 Docker）：

```bash
docker build --platform linux/amd64 --build-arg VERSION=local -t aetherlink:local .
```
